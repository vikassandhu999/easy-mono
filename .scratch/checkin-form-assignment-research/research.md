# Check-in Form Assignment: Competitor & Coach-Workflow Research

*Research date: 2026-08-14. Competitor findings cite official help centers, docs, and changelogs; community evidence is marked anecdotal.*

## Our current model (easy-mono source)

- `FormTemplate` is business-scoped: name, purpose (`intake` | `check_in`), sections/questions stored ON the template. Question types: text, number, boolean, date, select, multi_select, rating, weight, photo, service_type.
- `FormAssignment` links client → template **by reference** (`belongs_to :form_template`). Status: assigned / in_progress / completed / dismissed / missed. Carries due_date, priority, reminders.
- `FormSubmission` belongs to an assignment and stores a `question_snapshot` at submission time — historical answers are immune to later template edits.
- `CheckInSchedule`: client + template + frequency (once / weekly / biweekly / monthly) + next_due_on. A DB constraint allows only **one active schedule per client**.
- Consequence: forms are never copied to clients. Editing a template silently changes the questions every assigned client sees on pending/future assignments. There is no per-client customization; a coach wanting a variation for one client must create a whole new template.

**Research question:** should check-in forms be (a) assigned by reference to a shared template, (b) copied per client on assignment, or (c) a hybrid (template + per-client fork/override, versioning, opt-in propagation)? Which gives coaches the best UX?

## Competitor findings

### 1. ABC Trainerize — **copy (frozen instance)**

- Check-in Forms live in a central library ("Master Libraries > Forms", drag-and-drop builder: single answer, multiple answer, text answer, rating 1–10; required/optional toggles) and are then *scheduled* onto a client's calendar or a Master Program calendar. ([Sharing Check-In Forms with Clients](https://help.trainerize.com/hc/en-us/articles/31369316335124-Sharing-Check-In-Forms-with-Clients))
- The scheduled instance is a snapshot at scheduling time. The docs are explicit: "If the Check-in Form is already scheduled on a Master Program or a client's calendar, updates won't apply automatically. You'll need to re-schedule the form for the changes to take effect." (same article)
- No per-client content editing: forms "can only be created by the Account Owner or Admins"; trainers can only schedule existing forms. Per-client variation happens by scheduling different forms/dates, not editing a form for one client. (same article)
- Scheduling: "schedule one or multiple forms on a specific day and/or set-up repeating options for recurring check-ins" — multiple forms allowed, even same day. Exact frequency options not enumerated. Forms in a Master Program are anchored to the program's day structure; anchoring to client start date specifically: not documented. (same article)
- Auto-assignment: separate Onboarding Forms can be "enabled as part of the initial account setup process" (appear right after a new client sets a password) or scheduled into a Master Program. ([How to Create and Manage Onboarding Forms](https://help.trainerize.com/hc/en-us/articles/48660477450388-How-to-Create-and-Manage-Onboarding-Forms))
- Group auto-assign is indirect: "any clients added to the Group will automatically be subscribed to that Master Program," so forms scheduled in that program reach the group. ([How to Attach a Master Program to a Group](https://help.trainerize.com/hc/en-us/articles/115004510723-How-to-Attach-a-Master-Program-to-a-Group))
- Effect of edits on past submissions: not documented.

### 2. TrueCoach — **hybrid (copy per client + opt-in sync)**

- TrueCoach has no dedicated check-in-form feature; its docs tell coaches to build check-ins/questionnaires as *workouts*: "Build out your check-in with the workout builder... the tasks you put here are not limited to just workouts." ([Waivers, Questionnaires, Assessments and Check-in's](https://help.truecoach.co/en/articles/3363240-waivers-questionnaires-assessments-and-check-in-s))
- Assignment follows the Programs model: assigning a program copies its workouts to the client's calendar from a chosen start day. ([Programs](https://help.truecoach.co/en/articles/3047401-programs))
- Per-client customization is explicit and first-class: "any changes that you make to it on the client's workout calendar **will not effect** the program itself or any other clients workouts it's assigned to." (same article)
- Edit propagation is a coach-controlled toggle: with Sync ON, "Any changes that you make to workouts will instantly update on all assigned client's workout calendars"; with Sync OFF, changes don't touch client calendars, and deferred changes apply when Sync is re-enabled. (same article)
- No recurrence engine for check-ins — repetition is manual/structural (multi-week programs, copy/paste of workouts, multiple items per day). ([Copying and Pasting Workouts](https://help.truecoach.co/en/articles/3047914-copying-and-pasting-workouts), [Assigning Multiple Workouts in One Day](https://help.truecoach.co/en/articles/3047936-assigning-multiple-workouts-in-one-day))
- Onboarding is a documented *pattern*, not an automation: build an "Onboarding Sequence" program (Day 1 welcome, Day 2 questionnaire, Day 5 first check-in) and assign it manually when the client joins. ([Creating an Onboarding Sequence](https://help.truecoach.co/en/articles/3889427-creating-an-onboarding-sequence))
- Effect of synced edits on completed responses: not documented.

### 3. Everfit — **reference (auto-sync)**

- Forms are first-class library objects; only *published* forms can be assigned ("Only published forms can be added to a task or resource"). ([How to Create Forms & Questionnaires](https://help.everfit.io/en/articles/6633667-how-to-create-forms-questionnaires))
- Assigned tasks reference the library form, and propagation is automatic: "Any changes you make to a published form will sync with the clients' assigned tasks and resource collections automatically." (same article) — the same model easy-mono has today.
- Per-client question customization: not documented. The per-client layer is only the task wrapper (title, instructions, date, reminder). ([Assign a form to your client via tasks](https://help.everfit.io/en/articles/6633720-assign-a-form-to-your-client-via-tasks))
- Submissions are stored per date/time and browsable per response, with per-response PDF export; whether a template edit rewrites how old responses display is not documented. ([Export Form Responses as PDF](https://help.everfit.io/en/articles/8012101-export-form-responses-as-pdf))
- Recurrence via repeated tasks (paid plans): "repeat tasks daily, weekly, on particular dates of the week, or monthly," with granular series editing ("This & Upcoming" vs "Only This Task"). Biweekly is not listed. ([How to set up repeated tasks](https://help.everfit.io/en/articles/5484091-how-to-set-up-repeated-tasks))
- Multiple concurrent recurring form tasks per client: no documented limit (repeats are per task).
- Auto-assignment is the strongest of the set: Onboarding Flow can include up to 2 forms delivered to every new client automatically ([Introducing: Onboarding Flow](https://help.everfit.io/en/articles/8440572-introducing-onboarding-flow)); Form Triggers auto-assign programs/forums based on a client's answer to a trigger question ([Form triggers](https://help.everfit.io/en/articles/9595362-form-triggers)); Autoflow templates deliver "pre-made weekly check-ins, progress updates, and habit reminders" to whole groups. ([Autoflow Overview](https://help.everfit.io/en/articles/3661707-autoflow-overview-how-to-automate-your-training-business))

### 4. PT Distinction — **copy (per-client fork expected)**

*Sourcing note: support.ptdistinction.com did not resolve during research; findings come from PT Distinction's own tutorial articles on ptdistinction.com — primary vendor sources, but marketing-adjacent.*

- Assignment is an explicit **copy** operation from the Library: "Come down to the three dots next to the form and select copy to clients or group." ([Forms and Questionnaires on PT Distinction](https://www.ptdistinction.com/blog/forms-and-questionnaires-on-pt-distinction))
- Copy-then-edit is the stated philosophy for templates generally: "use them for your clients and groups of clients in one click, or you can edit them as much as you like to suit each individual." ([Creating and Using Templates](https://www.ptdistinction.com/blog/creating-and-using-templates))
- Per-client customization is supported by placement: "if you want to make a custom form and then share it later, put it in your library and if you want to do it just for one client, then go to the client dashboard" — a form can exist for exactly one client. ([Quickly add a form or questionnaire](https://www.ptdistinction.com/blog/quickly-add-a-form-or-questionnaire-for-your-clients))
- Group sends confirm copy semantics: a non-group program "simply copies the content to their personal account." ([Introduction to PT Distinction Groups](https://www.ptdistinction.com/blog/introduction-to-pt-distinction-groups))
- Edit propagation after assignment: not documented (copy semantics imply independence, but no article states it for forms directly). Completed submissions are "saved and sealed for your records." ([Forms and Questionnaires](https://www.ptdistinction.com/blog/forms-and-questionnaires-on-pt-distinction))
- Recurrence for forms specifically: not documented; recurrence exists for the adjacent results-tracking items (e.g., daily for two weeks). ([Results Tracking upgrade](https://www.ptdistinction.com/blog/feature-upgrade-results-tracking))
- Auto-assignment is strong: package purchase auto-adds clients to a "Welcome Group" where welcome messages and "assessment forms (PAR-Q, lifestyle questionnaire) are unlocked in their schedule"; onboarding groups "drip feed" forms into the account. ([Streamline your PT business systems](https://www.ptdistinction.com/blog/how-to-streamline-your-personal-training-business-systems), [Onboard new clients in under 10 seconds](https://www.ptdistinction.com/blog/perfectly-onboard-new-clients-in-under-10-seconds))

### 5. CoachRx (OPEX) — **hybrid (template reference + snapshot-per-send)**

- Weekly check-ins are assigned by choosing a template + day of week: "Click Weekly and then choose the template and day of the week you want to assign the check-in"; it then "sends automatically on chosen day." ([Automate weekly check-ins](https://www.coachrx.app/articles/pro-tip-automate-weekly-check-ins), [Consultations](https://intercom.help/coachrx/en/articles/5829043-consultations))
- Snapshot-per-send semantics, stated twice: consultation templates — "Updates apply to future consultations only (existing consultations unchanged)" ([Consultations](https://intercom.help/coachrx/en/articles/5829043-consultations)); intake forms — "Changes to a template will apply to future sends but will not retroactively change forms that have already been sent or completed… Completed forms remain intact even if the template is edited or deleted." ([Intake Forms](https://intercom.help/coachrx/en/articles/14310919-intake-forms-creating-customizing-managing))
- Cautionary changelog entry (April 2026): "Deleting a weekly check-in question now cleanly removes all associated historical answers" — question deletion cascades into history, framed as a feature. ([CoachRx changelog](https://www.coachrx.app/change-log))
- Per-client customization = one template per client: "you can even create a different template for each client based on their priorities"; "Create unlimited templates." ([Automate weekly check-ins](https://www.coachrx.app/articles/pro-tip-automate-weekly-check-ins)) Editing a single assigned instance: not documented.
- Cadences: weekly check-ins, monthly consultations, one initial consultation per client. Multiple concurrent weekly check-ins: not documented. ([Consultations](https://intercom.help/coachrx/en/articles/5829043-consultations))
- Auto-assignment: intake forms auto-send on client creation ("New clients automatically receive these forms as part of their welcome email"); since Nov 2025 coaches "can now select which intake form is sent when adding clients, customizing onboarding per client type." ([Platform walkthrough](https://intercom.help/coachrx/en/articles/7904184-coachrx-platform-walkthrough), [changelog](https://www.coachrx.app/change-log))

### 6. Practice Better — **copy (dispatch-instance model)**

- Each send is a per-client instance: a completed form "remains read-only," and resending "creates a copy with your client's existing answers for them to update. You will see two forms in their Forms & Waivers section (the original and the copy)." ([Resending Forms](https://help.practicebetter.io/hc/en-us/articles/360016094171-Resending-Forms-and-Sending-Form-Reminders-to-Clients))
- Even Practice Better's own pre-built library is copy-on-take: "Select a form template from the list to add and customize" into your account. ([Pre-Built Form Templates](https://help.practicebetter.io/hc/en-us/articles/360016097151-Adding-Pre-Built-Form-Templates-from-Practice-Better-s-Template-Library))
- Per-client customization of an already-sent instance: not documented; the mechanism is duplicating forms in the practice library and choosing what to send per client. ([Creating Forms and Waivers](https://help.practicebetter.io/hc/en-us/articles/115004332288-Creating-Forms-and-Waivers-Manually-in-Practice-Better))
- Cross-version reporting uses question-ID matching with documented lossiness: "some responses may be omitted from the report if the system is unable to associate answers to the questions included in the new version of the form." ([Viewing Form Responses](https://help.practicebetter.io/hc/en-us/articles/360045688612-Viewing-Form-Responses))
- Recurrence engine: "ongoing, recurring forms… on a daily, weekly, or monthly recurring basis," with start date, dispatch time, upcoming-schedule preview, multiple forms per schedule, and pause/resume/edit of the schedule itself. ([Sending Recurring Forms](https://help.practicebetter.io/hc/en-us/articles/360056038371-Sending-Recurring-Forms))
- Auto-assignment: forms auto-send after booking or package confirmation, with timing offsets and an "Allow clients to complete form(s) multiple times" option pitched explicitly for "weekly check-in forms"; tag automations and unlimited stacked automations exist. Known gap: no auto-resend of uncompleted forms. ([Sending Forms Automatically](https://help.practicebetter.io/hc/en-us/articles/360004451752-Sending-Forms-Automatically-after-Bookings-and-Packages-are-confirmed), [Setting up Automations](https://help.practicebetter.io/hc/en-us/articles/360004499811-Setting-up-Automations))

### 7. Healthie — **reference (answers preserved, edits flow to future fills)**

Healthie has a public API, so its data model is directly inspectable — and it is the closest analogue to ours.

- `CustomModuleForm` is "the form template — the container that holds all the questions" (each question is a `CustomModule`); `FormAnswerGroup` is the submission, referencing the template via `custom_module_form_id`. ([Filled Out Forms guide](https://docs.gethealthie.com/guides/filled_out_forms/), [CustomModuleForm object](https://docs.gethealthie.com/reference/2024-11-01/objects/custommoduleform), [FormAnswerGroup object](https://docs.gethealthie.com/reference/2024-07-01/objects/formanswergroup))
- `FormAnswer` is a partial snapshot: it stores the answer value plus `label`/`displayed_answer`, but the question itself is a *reference* (`custom_module_id`). No full question-snapshot or template-versioning mechanism is documented. ([Filled Out Forms guide](https://docs.gethealthie.com/guides/filled_out_forms/))
- Edit propagation, per the help center: "If you edit an intake form that has already been sent to some clients, as long as they have started or completed the form, those changes will not be reflected in previously completed forms… If this form is already added to an intake flow, new clients will automatically see the updated version." For a real revision, Healthie's recommended path is to create a *new* form, swap it into intake flows, and re-request completion. ([Edit or delete an intake form](https://help.gethealthie.com/article/1107-edit-or-delete-an-intake-form), [Update an intake form](https://help.gethealthie.com/article/896-update-an-intake-form-for-clients-to-complete))
- Deleting a template kills aggregate exports, but completed forms stay viewable on the client profile. ([Edit or delete an intake form](https://help.gethealthie.com/article/1107-edit-or-delete-an-intake-form))
- Per-client customization: not documented — no per-client fork exists; the customization granularity is per-*group* via intake flows, or a separate template. ([Intake Flows v2](https://help.gethealthie.com/article/1162-getting-started-intake-flows-v2))
- The per-client assignment/recurrence is its own object referencing the shared template: `RequestedFormCompletion` with `is_recurring`, `frequency` (Daily/Weekly/Monthly), `weekday`, `monthday`, `recurrence_ends`. ([Forms guide](https://docs.gethealthie.com/guides/forms/))
- In-product recurrence: daily, weekly, multiple-times-per-week, every-2-weeks, monthly, quarterly, with day-of-week and optional end date; settable per client, per group, or from the form. Multiple concurrent recurrences are listed/managed in the UI; no documented limit. ([Having clients complete the same form more than once](https://help.gethealthie.com/article/507-having-clients-complete-the-same-intake-form-more-than-once))
- Auto-assignment: Intake Flows "are tied to client groups, and are triggered when a client is added, or moves, into a new group"; Programs can send a weekly survey cadence; forms can attach to client packages. ([Intake Flows v2](https://help.gethealthie.com/article/1162-getting-started-intake-flows-v2), [Programs weekly survey](https://help.gethealthie.com/article/379-using-programs-to-send-a-weekly-survey-intake-form), [Form on a package](https://help.gethealthie.com/article/986-add-a-form-to-a-client-package))

### 8a. Hevy Coach — **no form feature**

- The official features index (Dashboard, Client Management, Workout/Plan Builders, Progress Tracking, Exercise Library, Client Chat, Coaching Teams, Grow) has no forms, questionnaires, surveys, or check-in feature. ([hevycoach.com/features](https://hevycoach.com/features/))

- Client feedback flows through chat/activity feed instead. ([Client Chat](https://hevycoach.com/features/client-chat/)) All assignment-model questions: not applicable.

### 8b. My PT Hub — **reference (edit propagation undocumented)**

- Forms are shared library templates assigned by reference to individuals or groups: "Previously, when you created a form it would be assigned to all clients automatically, but now you have the ability to assign a form to an individual or group of clients." ([Assign forms to clients](https://support.mypthub.net/hc/en-us/articles/360026633754-Assign-forms-to-clients))
- Builder question types: multiple-choice, 1–10 scale, number/text, yes/no, star ratings, e-signature. ([Create a form](https://support.mypthub.net/hc/en-us/articles/360026585314-Create-a-form))
- Per-client customization: not documented — the "Updating a client's Forms" article only covers (re)assigning library forms. ([Updating a client's Forms](https://support.mypthub.net/hc/en-us/articles/360026737953-Updating-a-client-s-Forms))
- Edit propagation / versioning after assignment or submission: not documented.
- Check-Ins support "a repeat setting of daily, weekly, bi-weekly, or monthly… automatically sends the check-in to the client on your chosen schedule from a specified start date", with reminders and an overdue area. (First-party but blog, not help center: [How to automate client check-ins](https://www.mypthub.net/blog/how-to-automate-client-check-ins-for-online-coaching/))
- Auto-assignment: new clients are auto-assigned a PAR-Q; a per-form "Show Form In Sign Up" toggle inserts any form into activation; packages can auto-assign forms/plans. ([Client management features](https://www.mypthub.net/features/client-management-features/), [Add a form to the activation process](https://support.mypthub.net/hc/en-us/articles/360026801673-Add-a-form-to-the-activation-process))

## Coach workflow findings

*Sourcing note: Reddit blocked crawling during this research, so first-person community anecdotes come from platform feature-request boards (real coach comments, marked anecdotal) and vendor content (marked where the source is a competitor's marketing blog).*

### How many distinct check-in forms does a typical coach run?

Best-supported answer: **intake + one recurring weekly check-in is the floor; a deeper monthly review is a common second recurring form.** All evidence is platform best-practice guidance, not measured behavior — no survey data on median form counts was found.

- Gymkee's coach-education guide prescribes exactly two recurring forms: a weekly check-in (<5 min: energy/adherence/sleep ratings) and a monthly review (15–30 min: measurements, goal reassessment). ([gymkee.com check-in template guide](https://gymkee.com/blog/personal-training-client-check-in-template/))
- Coachway recommends a single streamlined weekly form of 8–12 fields: "Weekly is the default for most clients. Bi-weekly works for stable maintenance phases." Daily check-ins discouraged. ([coachway.io check-in guide](https://coachway.io/articles/how-to-do-client-check-ins-online-coach/))
- HubFit publishes a distinct monthly check-in template alongside weekly ones (vendor content). ([hubfit.com monthly template](https://hubfit.com/blog/monthly-check-in-form-template-for-online-coaches-and-personal-trainers))
- Everfit's forms launch post frames the canonical lifecycle as "an intake form, weekly check-in, or post-program evaluation" — three form types per client lifecycle. ([blog.everfit.io forms launch](https://blog.everfit.io/introducing-forms-and-questionnaires))
- OPEX/CoachRx methodology: weekly check-in form + monthly consultation. ([CoachRx Consultations](https://intercom.help/coachrx/en/articles/5829043-consultations))

### Do coaches customize per client, or per program/segment?

Direct evidence points to **per-program / per-population, not per-individual client**.

- Trainerize "Multiple consultation forms" feature request (82 votes, open): coaches want different forms per client *type* — "I work with pre and postnatal women... they require different par-qs"; "I have programs that are personalized and require more detail whereas other self-paced programs don't." (Anecdotal, individual coach comments.) ([ideas.abcfitness.com #37918999](https://ideas.abcfitness.com/forums/167887-coach-trainer-abc-trainerize/suggestions/37918999-multiple-consultation-forms))
- Trainerize's own roadmap language mirrors segmentation: forms "across different programs and client types." ([Trainerize check-in launch blog](https://www.trainerize.com/blog/trainerize-update-check-in-forms-are-here-engage-smarter-and-transform-clients-lives/))
- PT Distinction's recommended workflow is batch: one weekly form assigned to "All Clients" in under 30 seconds — the platform optimizes for one form across the roster. ([ptdistinction.com 30-second check-ins](https://www.ptdistinction.com/blog/30-vs-10-give-a-weekly-check-in-form-to-all-of-your-clients-in-under-30-seconds))
- Coachway explicitly favors standardization over per-client tailoring — adapt by phase (maintenance vs active), not per individual. ([coachway.io](https://coachway.io/articles/how-to-do-client-check-ins-online-coach/))
- No direct evidence found for cutting-vs-bulking form variants specifically; the segmentation evidence is population/program-based (prenatal, athletes, nutrition-only, self-paced vs personalized).

### Template-edit propagation pain

The industry has split into incompatible models, and each platform's docs warn about its own footgun — help articles of this kind are indirect evidence that support tickets pile up around the behavior:

- Trainerize (snapshot): "updates won't apply automatically. You'll need to re-schedule the form" — the coach's cost is manual re-scheduling across clients. ([help.trainerize.com](https://help.trainerize.com/hc/en-us/articles/31369316335124-Sharing-Check-In-Forms-with-Clients))
- Everfit (live-sync): edits "sync with the clients' assigned tasks... automatically" — docs silent on what happens to prior responses. ([help.everfit.io](https://help.everfit.io/en/articles/6633667-how-to-create-forms-questionnaires))
- Practice Better (versioned, ID-matched): when a form changes between submissions, responses are matched by question ID, "however, some responses may be omitted from the report if the system is unable to associate answers to the questions included in the new version of the form" — explicit, documented data-visibility loss from template edits. ([Viewing Form Responses](https://help.practicebetter.io/hc/en-us/articles/360045688612-Viewing-Form-Responses))
- Healthie (append-only reporting): "If you make edits to your form, old responses will still appear," and exported reports show "All fields that ever existed in the form (across all clients & versions of the form)" — history survives at the cost of ever-widening reports. ([Healthie form-response reports](https://help.gethealthie.com/article/355-intake-forms-charting-template-reports))
- No first-person "I edited my template and it changed for live clients" complaint was found directly (Reddit unreachable); the documentation-warning evidence is indirect.

### Per-client copy pain

- My PT Hub's older single-use forms: "Each form can only be filled out once, requiring coaches to assign new forms every week" — direct description of per-copy administrative burden. (Caveat: source is HubFit, a competitor comparison blog.) ([hubfit.com check-in comparison](https://hubfit.com/blog/which-platform-offers-the-best-check-in-system-for-online-fitness-coaches))
- TrueCoach's workaround model (check-ins embedded in workouts, copied into every program per client) lacks "reusable templates or a centralized area for response review." (Same competitor-blog caveat; TrueCoach's own docs confirm the workout-builder approach.) ([help.truecoach.co](https://help.truecoach.co/en/articles/3363240-waivers-questionnaires-assessments-and-check-in-s))
- The pre-platform version of per-client copies (spreadsheets/Google Forms): "every new client creates roughly proportional work: a new tab, a new payment setup, a new check-in schedule." ([assistantcoach.fit](https://assistantcoach.fit/blog/google-sheets-to-fitness-coaching-software/))
- PT Distinction's whole pitch — all clients in 30 seconds vs manual distribution — is itself evidence that per-client distribution was the pain being sold against. ([ptdistinction.com](https://www.ptdistinction.com/blog/30-vs-10-give-a-weekly-check-in-form-to-all-of-your-clients-in-under-30-seconds))
- **"Content drift" at 30–100 clients specifically is unproven by these sources** — plausible from the mechanics, but no coach was found describing it in those words.

### Feature-request signals

- The single biggest demand signal in the space: Trainerize's "sending weekly check-in survey/forms" idea — **2,406 votes**, open for years, completed Oct 2025. Coach comments (anecdotal): "This is one of the most important parts of coaching"; "The only feature that is missing from the platform that I have started trialing other coaching apps"; "rather than sending my clients forms every single time." ([ideas.abcfitness.com #34832734](https://ideas.abcfitness.com/forums/167887-feature-requests-ideas-and-suggestions/suggestions/34832734-sending-weekly-check-in-survey-forms-clients-have))
- Immediately after Trainerize shipped ONE check-in form, the follow-up request became "multiple forms" (v1 capped at one form, 10 questions; multiple forms "across different programs and client types" promised in the completion note). Strong signal that a single-template-per-coach model is under-modeled. ([Trainerize launch blog](https://www.trainerize.com/blog/trainerize-update-check-in-forms-are-here-engage-smarter-and-transform-clients-lives/))
- Everfit's post-launch trajectory shows where demand goes after basic forms ship: conditional form triggers, response-comparison views, scheduling automation — from "let me make a form" to "automate assignment and compare responses over time." ([Form triggers](https://help.everfit.io/en/articles/9595362-form-triggers), [blog.everfit.io July 2026](https://blog.everfit.io/july-2026-new-features))

## Verdict & ranked recommendations

### Verdict: keep the reference model. Do not copy forms per client. Harden the edges instead.

Three lines of evidence converge on this:

1. **Coaches segment by population, not by individual.** Every piece of direct workflow evidence — the Trainerize "multiple consultation forms" request (prenatal vs general, personalized vs self-paced), CoachRx's "different template per client type," PT Distinction's assign-to-All-Clients-in-30-seconds pitch, Coachway's explicit standardize-don't-tailor guidance — points at the unit of customization being the *template*, not the client. The demand we'd serve with per-client question editing is better served by making templates cheap to duplicate and assign. No platform with a reference model (Everfit, Healthie, My PT Hub) offers per-client question editing, and no coach demand for it surfaced.

2. **The copy model's pain is documented; the reference model's pain is fixable.** Copy-model platforms generate exactly the maintenance burden our reference model avoids: Trainerize coaches must re-schedule a form on every client to ship an edit; Practice Better resends multiply instances in the client's file and its cross-version reports drop answers; My PT Hub's old single-use forms meant re-assigning every week. The reference model's one real hazard — a template edit silently reaching clients mid-flow — is a narrow, patchable edge, and we already own the hard half of the fix: `FormSubmission.question_snapshot` makes completed history immune, which is precisely the guarantee CoachRx ("completed forms remain intact") and Healthie ("changes will not be reflected in previously completed forms") advertise.

3. **The best-in-class reference platforms show the roadmap.** Healthie (reference + per-assignment recurrence object + multiple concurrent recurrences + group-triggered intake flows) is structurally our schema plus three features. Everfit's post-launch trajectory (onboarding auto-assign → triggers → comparison views) shows where coach demand goes once basic forms exist: automation of assignment, not per-client authoring.

### Ranked improvements (coach-UX impact ÷ implementation cost)

1. **Allow multiple active `CheckInSchedule`s per client** — highest impact, lowest cost. The canonical coach stack is weekly check-in **plus** monthly progress review (Gymkee, CoachRx weekly+monthly consultations, Healthie multiple concurrent recurrences, Practice Better multiple forms per schedule). Our one-active-schedule DB constraint makes the industry-standard stack impossible. Fix: relax the unique constraint to `(client_id, form_template_id)` so one client can run distinct templates concurrently; UI becomes a list instead of a single slot.

2. **Auto-assign intake on client onboarding** — high impact, low-moderate cost. Universal across competitors (CoachRx auto-sends on client creation, Everfit Onboarding Flow, PT Distinction Welcome Group, My PT Hub PAR-Q, Practice Better booking automation) and the mechanism behind Trainerize's 2,406-vote thread was "stop making me send forms manually." Fix: a business-level setting naming an intake `FormTemplate`; client activation creates the `FormAssignment`. Tags/groups-based triggers can come later — start with the one hook every platform has.

3. **Snapshot questions onto `FormAssignment` at creation (pin-at-send)** — moderate impact, low cost. Converts our silent-propagation hazard into the CoachRx/Healthie contract coaches already understand: "edits apply to future sends only; anything already sent is unchanged." Copy the template's question set into a `question_snapshot` on the assignment when it's created (the submission-time snapshot stays as the archival record). This also kills the mid-fill mutation edge case for `in_progress` assignments. This is cheaper and strictly safer than full template versioning — we get versioning's user-facing guarantee without a versions table.

4. **"Duplicate template" / save-as-copy flow** — moderate impact, very low cost. This is how reference-model platforms serve segmentation (CoachRx "unlimited templates… a different template for each client type"; Trainerize's roadmap answer to the multiple-forms request). One endpoint + one button; makes "I need a prenatal variant" a 10-second task instead of manual re-entry.

5. **Per-client schedule anchoring / start date** — low-moderate impact. My PT Hub and Practice Better let recurrence run "from a specified start date." Our `next_due_on` already carries per-client anchoring; the remaining work is UI (pick first due date on schedule creation) — do it as polish, not a project.

6. **Per-client question overrides / assignment forks** — **recommend against.** No reference-model competitor has it, no coach demand evidence surfaced, and it reintroduces the copy model's drift problem (documented in Practice Better's lossy cross-version reports and Trainerize's re-schedule tax) into our cleanest property. If a coach truly needs a one-client variant, recommendation #4 (duplicate template) covers it with zero new schema.

7. **Full template versioning (versions table, pinned pending assignments)** — **defer.** Recommendation #3 delivers the same coach-visible behavior for the cost of one JSONB column. Build real versioning only if we later need cross-version answer analytics (the thing Practice Better does lossily and Healthie does by ever-widening reports) — that's an analytics feature, not an assignment-model feature.

### Migration note

No data migration pain: (a) drop/replace the single-active-schedule unique index with `(client_id, form_template_id)` uniqueness on active schedules; (b) add `question_snapshot` (jsonb, nullable) to `form_assignments`, populated on create going forward — render falls back to the live template when null, so existing rows keep today's behavior; (c) duplicate-template is a context function + endpoint, no schema; (d) onboarding auto-assign is one nullable `intake_form_template_id` reference on the business (or a settings row) plus a hook in client activation. Everything ships independently, in the ranked order above.

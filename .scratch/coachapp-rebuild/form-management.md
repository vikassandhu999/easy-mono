# Manage reusable forms

When my form library changes, I need to retire or remove a form without breaking client answers or ongoing check-ins. This is an occasional phone or desktop task. The costly mistakes are deleting referenced forms, unexpectedly changing the intake for future invitations, and overwriting another coach's edits.

Keep question editing focused. Manage form opens a dedicated page from a saved editor, preserving the originating list filters. It shows the saved name, status, question preview, server-owned assignment/schedule/response counts and the intake currently used by invitations. Archive and Restore are clear primary lifecycle actions. Deletion has a named confirmation and is available only when the server reports no assignments, no schedules and no built-in identity. Explain unavailable deletion beside the action. Archiving keeps assigned forms and existing schedules working, prevents new selections and clears an explicit default; restoring does not silently make it the default again.

Default intake actions explain future invitations and automatic selection. Clearing an explicit choice does not mean invitations have no intake; show the actual server-selected fallback after the write. The Forms list defaults to Active and offers Archived and All using the shared shadcn selector and server cursor filtering. Assignment pickers request Active.

All writes check the revision reviewed by the coach; stale changes offer an explicit refresh. Failed and uncertain lifecycle writes keep a retry action, recover a matching saved result and guard session changes. Deletion checks usage again on the server and retains database foreign-key protection against concurrent references. Backend default changes serialize on the business, and archiving clears the default flag atomically. Form editing uses the same revisions and preserves drafts on stale saves.

Verify real API archive/restore, automatic/default intake selection, used and built-in deletion restrictions, successful unused deletion, counts, status paging/search, archived picker exclusion, assigned responses and continuing schedules, stale edits/actions, lost responses and account replacement at 375px and 1280px. Run generated API, build, scoped Biome, repository checks and backend precommit. No automatic commits.

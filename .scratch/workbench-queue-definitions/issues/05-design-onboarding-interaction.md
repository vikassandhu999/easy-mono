# Design the Onboarding queue interaction

Type: prototype
Status: open
Parent: [Coach workbench v1 delivery](../map.md)

## Question

How should Onboarding explain and action a stale invitation, an overdue intake, or both?

Produce a rough interaction covering reason copy, row actions, resend behavior, intake follow-up, ordering when reasons overlap, and the rename from New clients to Onboarding. The separate Recent clients metric has no placement in this effort.

# Split Nutrition by responsibility and keep Library, Programming, and Diary separate

Nutrition is divided into Library, Programming, and Diary modules so each interface owns one coherent responsibility. Library owns Foods and Recipes as separate aggregates, plus Portions and nutrient calculation. Programming owns Nutrition Templates, Client Nutrition Plans, Menus, Assignment, and Coverage. Diary owns Nutrition Days and relational frozen offered options and planned items that later client commands can address. We rejected a pass-through Nutrition facade because it would hide ownership, rejected generic food, plan, and log resource modules because they exposed storage operations instead of domain behavior, and rejected collapsing Food and Recipe into one item type because they have different composition and Portion rules.

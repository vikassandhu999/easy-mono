# Client plan dates and lifecycle

When a client's schedule changes, a coach needs to adjust when their assigned plan applies, retire it, or bring it back without changing the reusable template. This is occasional work on mobile and desktop. The costly mistakes are overlapping two plans, losing access after setting an end date, deleting logged history, and overwriting another coach's update.

A date disclosure in the worksheet would be quick to add but mixes scheduling with prescription authoring and does not solve access to ended plans. Use an All assigned plans destination from Client overview, leading to client-scoped plan management. Keep Personalize as the separate builder action. Management identifies the client, plan and server lifecycle; dates are the primary task, with archive/restore and permanent deletion below.

Both resource lists must page and search on the server and include ended, incomplete and archived plans. Training already has a coach client-scoped cursor endpoint with Active/Archived filters, but lacks search. Nutrition only exposes current/upcoming coverage to coaches, so add a client-scoped cursor list with search/archive filtering. The actor must pass client visibility authorization before querying. Never derive these selections or totals in the browser.

Date editing uses the existing revisioned plan PATCH. Start is required for coverage; a blank end means no end date. The server rejects reversed dates and overlaps. Capture the displayed revision, retain drafts on failures, and reconcile interrupted writes by reading the same plan. A stale save must require reviewing the latest version. A saved ended plan remains reachable in All assigned plans. Keep the existing client-local calendar semantics and frozen history.

Archive removes active coverage; restore may conflict with a newer plan and must preserve the archived plan when rejected. Explain these consequences separately from template management. Delete preserves the documented frozen activity history; verify actual foreign-key behavior before exposing it. Account changes cancel navigation/cache work from late completions.
